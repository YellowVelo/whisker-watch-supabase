## Before You Approve This

- **Scope grew from "fix Catch Up" to a full, app-wide audit — you confirmed this.** What Lynn reported was one broken screen (Catch Up's bulk-apply and per-day arrow). Investigating it found the actual cause is a design gap that affects every popup/full-screen surface in the app, not just Catch Up — so this spec fixes the gap everywhere it exists (16 files), not just the one screen that happened to surface it, per the "not a band-aid" direction and the research discussion confirming a named, centralized scale (matching how Chakra UI, and eventually Ant Design after their own version of this exact bug, both solved it).
- **A related-but-different bug was found nearby — you asked for it to be fixed here too, so it's now in scope.** Digging into exactly which components are affected (not just going on the earlier surface-level read) found the real picture is narrower than first described:
  - **`AskWyskerSheet.jsx` turns out NOT to be affected**, on closer inspection. It's mounted by `AskWyskerProvider` (`src/lib/AskWyskerContext.jsx`) as a sibling of the routed page inside `AppShell.jsx`, not nested inside that page's own `PageTransition` wrapper — so it never sits behind the transformed ancestor that causes this bug. Correcting the earlier draft, which had this wrong.
  - **`PetSymptoms.jsx`'s "Log Symptoms" overlay (line 138) is genuinely affected**, confirmed: it's rendered as a second, conditional child directly inside that page's own `<PageTransition>` (line 163), which Framer Motion gives a CSS transform even at rest — the exact mechanism `BottomSheet.jsx`'s own comment (lines 22–42) describes. Scroll the Symptom Timeline down first, then tap "Log symptoms," and its header/footer render far below the visible screen instead of pinned to it.
  - This is now fixed as part of this spec (see Functional Requirements #5 and Technical Spec) by portaling it to `document.body`, the same technique already proven for `BottomSheet`/`CatchUpFlow`/`OnboardingShell`, and giving it the new `overlay` layer. While touching it, it also gains the same `role="dialog"`/focus-trap treatment those three components already have (via the existing shared `useFocusTrap` hook) — leaving it without that, the one time it's being rebuilt this way, would just recreate the exact "third copy has the gap" problem spec 0045 was written to close.
- **Found and now removed as part of this spec: 11 unused UI library files.** `src/components/ui/{sidebar,resizable,calendar,input-otp,navigation-menu,dropdown-menu,context-menu,menubar,popover,hover-card,tooltip}.jsx` all carry hardcoded `z-50`/`z-[1]` values but are confirmed (import search across all of `src/`) never rendered anywhere in the app — dead scaffolding left over from the shadcn/ui starter kit. Since you asked for this cleaned up now: these 11 files are deleted as part of this spec, not migrated onto the new scale (nothing to migrate — deleting removes the stale numbers along with the files). This also means any of their own sub-dependencies (e.g. `resizable.jsx`'s `react-resizable-panels` import) get checked for other users before its `package.json` entry is considered for removal too — see Technical Spec.
- **Banner-vs-popup ordering was investigated and decided, not left as a guess.** Checking each banner's actual on-screen position (not just its z-index number) found `AccountTypeBanner`/`OfflineBanner` are thin strips pinned to the very top of the screen — every full-screen overlay already pads below them, and bottom-anchored popups never reach that high, so neither one ever actually overlaps a popup regardless of which one "wins" numerically. `IosInstallBanner` is different: it sits near the *bottom* of the screen, in the same band as a `BottomSheet` popup's own primary action button (Save/Continue) — and since it already outranks `BottomSheet` today, it can genuinely sit on top of and block that button when both are visible on iOS Safari, a real (if rare) collision, not a hypothetical. You chose to treat all three banners identically rather than special-case `IosInstallBanner` alone: **popups now outrank all three banners** in the new scale. Because the top-anchored banners never spatially overlapped a popup anyway, this has zero visible effect on them — it fixes only the one real conflict (`IosInstallBanner` over a sheet's Save button), with one uniform rule instead of an exception carved out for a single component.
- No conflicts with CLAUDE.md's locked Vibe/Symptom Count data model — this touches zero check-in logic, only overlay/popup shell markup and one shared constants file.

## Functional Requirements

1. **Every popup — a bottom sheet, a check-in form, a confirmation dialog — must always visually appear on top of any full-screen flow it was opened from.** Today, a popup opened from inside Catch Up's Exceptions screen (or, in the future, from inside the pet-onboarding wizard) can render invisibly behind that screen instead of on top of it, because the two surfaces "compete" using hand-picked numbers that happen to be in the wrong order.
2. **The app must have one single, written-down list of what's allowed to cover what** — ordinary page content, then full-screen flows (Catch Up, Onboarding, Ask Wysker, editing a pet's symptoms), then system banners, then popups/sheets/dialogs, then toast notifications — so a developer adding a new screen picks from that list instead of guessing a number and hoping it doesn't collide with something already in the app.
3. **Fixing today's specific bug (Catch Up's "Apply to N days" and per-day arrow doing nothing) is a direct consequence of #1 and #2, not a separate patch** — once popups are guaranteed to outrank full-screen flows by design, Catch Up's bulk-apply sheet and detail sheet both become visible and clickable again, with no special-case code just for Catch Up.
4. **This does not change what any screen looks like, what it says, or what it does** — this is purely about stacking order (what's drawn in front of what), not visual design, wording, or behavior — with one exception, #5 below.
5. **The Symptom Timeline's "Log Symptoms" panel must stay correctly positioned on screen no matter how far down the Timeline was scrolled first.** Today, scrolling the Symptom Timeline down and then tapping the "+" (log symptoms) button can open a panel whose header and footer render far off-screen instead of pinned to the visible screen — the owner sees a mostly-blank page and has to scroll to find the form. This must behave the same way `BottomSheet`-based popups already do: correctly pinned to the screen regardless of scroll position.
6. **11 unused, never-rendered files left over from the app's original UI component library are removed**, along with the now-unused external packages they alone depended on. This is pure dead-code removal — nothing in the app currently uses these files, so nothing else changes.

## Acceptance Criteria

- Given a pet with 2+ missed check-in days, when the owner opens Catch Up, goes to Exceptions, selects 2 or more days, and taps "Apply to N days," then the bulk-apply sheet opens fully visible and usable (its buttons, its Off Day/Tough Day choices, its Save button all work), matching the same interaction that already works for the single-day version of this flow.
- Given the same Exceptions screen, when the owner taps the chevron/arrow on a single day, then that day's detail sheet opens fully visible and usable, not hidden behind the Catch Up screen.
- Given any other popup or dialog already in the app (e.g. the account-deletion confirmation, the co-owner invite dialog, the weight quick-log sheet), when it's opened from any screen — including a full-screen flow — then it renders on top of that screen, with no visual regression versus its current (already-working) appearance.
- Given the app's persistent chrome (top header, bottom tab bar) and system banners (Test/Demo Account indicator, offline banner, "Add to Home Screen" prompt), when any full-screen flow is open with no popup on top of it, then banners still show above the flow and the tab bar, exactly as today.
- Given the "Add to Home Screen" banner is visible (iOS Safari) and a `BottomSheet` popup with a bottom-pinned action button is opened at the same time, when both are on screen, then the popup's button is fully visible and tappable, not covered by the banner — closing the one real collision this ordering decision was made to fix. `AccountTypeBanner` and `OfflineBanner`'s on-screen appearance is unaffected either way, since neither ever spatially overlaps a popup.
- Given a developer adds a new full-screen flow or popup in the future, when they build it against the new shared layering list instead of picking their own number, then it automatically stacks correctly against every existing surface with no additional coordination required.
- Given the Symptom Timeline page has been scrolled down, when the owner taps "Log symptoms," then the panel opens correctly pinned to the visible screen (header at the top, form and its Save action reachable without scrolling to find them), identically to opening it from the top of the page.
- Given the Symptom Timeline's "Log Symptoms" panel is open, when inspected by assistive-technology tooling or navigated by keyboard, then it exposes `role="dialog"`/`aria-modal="true"`, traps Tab focus within itself, and closes on Escape — matching `BottomSheet`, `CatchUpFlow`, and `OnboardingShell`'s existing behavior (spec 0045).
- Given the 11 unused UI library files and their now-orphaned packages are removed, when the app is built, typechecked, and the full Playwright suite is run, then all three pass exactly as they did before the removal — proving nothing else depended on them.

## Technical Spec

- **New shared file, `src/lib/zIndex.js`:** exports one named scale, e.g.
  ```js
  export const Z = {
    chrome: 'z-[100]',  // persistent page chrome: AppHeader, BottomTabBar, PullToRefreshIndicator
    overlay: 'z-[200]', // full-screen flows: CatchUpFlow, OnboardingShell, AskWyskerSheet, PetSymptoms edit view
    banner: 'z-[300]',  // persistent system banners: AccountTypeBanner, OfflineBanner, IosInstallBanner
    popup: 'z-[400]',   // BottomSheet + Dialog/AlertDialog/Drawer/Select (all portal-based popups)
    toast: 'z-[500]',   // toast notifications
  };
  ```
  Large gaps (100 apart, not 10) between layers deliberately leave room for a future layer to be inserted without renumbering everything else — the same reasoning Chakra UI's own scale uses (its layers run 0 → 1800 in similarly large steps, not 1-2-3-4). Banner sits below popup (a deliberate change from today's raw numbers, where banners currently outrank everything) per the banner-vs-popup investigation above — chosen as one uniform rule for all three banners rather than special-casing `IosInstallBanner` alone, since the other two never spatially overlap a popup regardless of ranking.
- **Components migrated to reference `Z` instead of a hardcoded class** (relative order preserved from today except popup, which moves above both overlay and banner — the two actual inversions causing real bugs):
  - Chrome: `AppHeader.jsx` (was `z-40`), `BottomTabBar.jsx` (was `z-50`), `PullToRefreshIndicator.jsx` (was `z-50`)
  - Overlay: `CatchUpFlow.jsx` (was `z-[60]`), `OnboardingShell.jsx` (was `z-[60]`), `AskWyskerSheet.jsx` (was `z-[70]`), `PetSymptoms.jsx`'s full-screen edit view (was `z-50`)
  - Banner: `AccountTypeBanner.jsx` (was `z-[70]`), `OfflineBanner.jsx` (was `z-[70]`), `IosInstallBanner.jsx` (was `z-[70]`)
  - Popup: `BottomSheet.jsx` (was `z-50`), `ui/dialog.jsx` (was `z-50`), `ui/alert-dialog.jsx` (was `z-50`), `ui/drawer.jsx` (was `z-50`), `ui/select.jsx` (was `z-50`) — the 5 popup primitives actually used in the app today (confirmed by import search; the other 6 shadcn popup primitives are unused and deleted, see below)
  - Toast: `ui/toast.jsx` (was `z-[100]`)
- **`docs/foundation/0005 Design System.md`:** gains **Amendment #12**, locking this in as a rule, not just a code convention: "Stacking order (z-index) is never a hand-picked number. Every fixed/sticky surface must reference the named scale in `src/lib/zIndex.js` (chrome → overlay → banner → popup → toast). A new full-screen flow or popup picks a name from that list; it does not invent a number." This follows the same pattern as existing Amendment #8 (component de-duplication) — one canonical mechanism replacing several independent, ad-hoc ones.
- **`src/pages/PetSymptoms.jsx`'s "Log Symptoms" overlay (lines 137–154):** changed from an inline `<div className="fixed inset-0 z-50 ...">` rendered as a second child of that page's own `<PageTransition>`, to `createPortal(..., document.body)` — the same pattern `BottomSheet.jsx`/`CatchUpFlow.jsx` already use, for the same reason (escapes `PageTransition`'s always-on transform, so `fixed inset-0` anchors to the real viewport regardless of scroll position). Also gains `role="dialog"`, `aria-modal="true"`, and the existing shared `useFocusTrap` hook (no new hook logic needed — same call pattern `CatchUpFlow`/`OnboardingShell` already use), and moves onto the new `overlay` z-index layer (was `z-50`). The `--account-banner-height` CSS variable it reads for top offset still resolves correctly once portaled — confirmed this is the same variable `CatchUpFlow.jsx` already reads successfully from its own `document.body` portal today. No change to `SymptomLogForm` or any save/data behavior.
- **Deleted: 11 unused UI library files** — `src/components/ui/{sidebar,resizable,calendar,input-otp,navigation-menu,dropdown-menu,context-menu,menubar,popover,hover-card,tooltip}.jsx`, plus `src/hooks/use-mobile.jsx` (confirmed used only by `sidebar.jsx`, now orphaned too). Their npm packages, confirmed via dependency search to be imported nowhere else in `src/`, are removed from `package.json` in the same pass: `react-resizable-panels`, `input-otp`, `react-day-picker`, `@radix-ui/react-context-menu`, `@radix-ui/react-dropdown-menu`, `@radix-ui/react-menubar`, `@radix-ui/react-hover-card`, `@radix-ui/react-navigation-menu`, `@radix-ui/react-popover`, `@radix-ui/react-tooltip`. (`@radix-ui/react-slot`, imported by `sidebar.jsx` too, stays — also used by `button.jsx`, `form.jsx`, `breadcrumb.jsx`, all still in use. `vaul`, used by the still-active `drawer.jsx`, also stays.) A full `npm run build` + `npm run typecheck` after deletion confirms nothing else referenced any of this.
- **Not touched:** page-local `sticky` sub-headers inside individual pages (e.g. `Timeline.jsx`'s `sticky z-10`, `PetEdit.jsx`'s `sticky z-20`) — these are scoped to their own page's scroll container to stay under that page's own content, a different and unrelated concern from the app-wide fixed/portal overlay stack this spec addresses. See Non-Goals.
- **Design System compliance:** checked against `docs/foundation/0005 Design System.md` including all 11 existing Amendments — this is a new Amendment (#12) in the same spirit as #8, not a conflict with any existing one. No color, typography, spacing, or component-choice changes.
- **Constraints from CLAUDE.md / locked decisions:** none affected — no change to `daily_check_ins.status`, symptom counts, or any check-in save path; `checkinClient.js` is untouched. No schema or database changes.

## Repo Findings & Risks

- **Duplicate/overlapping functionality:** yes — this is the core finding. Every one of the 16 files listed above independently re-solved "how do I make sure I'm on top" with its own number and its own code-comment justification, several explicitly citing each other as precedent (`CatchUpFlow.jsx` cites `CareMenu.jsx`; `OnboardingShell.jsx`'s own comment says it was "modeled directly on `CatchUpFlow.jsx`'s overlay pattern," per spec 0045). This spec replaces all of that with one shared definition.
- **Technical debt nearby:** `PetSymptoms.jsx`'s full-screen "Log Symptoms" overlay was not portaled to `document.body` the way every other full-screen surface in the app is — the same class of debt spec 0045 flagged once already (in its Non-Goals) and deferred. It's not deferred a second time: fixed as part of this spec, see Technical Spec above. (`AskWyskerSheet.jsx`, originally suspected to have the same gap, was investigated and confirmed not affected — see "Before You Approve This.")
- **Orphaned features nearby:** yes — `src/components/ui/{sidebar,resizable,calendar,input-otp,navigation-menu,dropdown-menu,context-menu,menubar,popover,hover-card,tooltip}.jsx` (11 files) plus `src/hooks/use-mobile.jsx` were confirmed via import search to be unused anywhere in `src/` — shadcn/ui starter-kit scaffolding that never got wired up. Deleted as part of this spec, along with their now-orphaned npm packages — see Technical Spec.
- **Punch list / known issues in this area:** none found referencing z-index/layering specifically in `docs/planning/Wysker_Watch_Launch_Plan.xlsx`. This spec originates from a live bug report (Catch Up bulk-apply), not a pre-existing tracked task.

## Non-Goals

- Does not touch page-local `sticky` sub-headers within individual pages' own scroll containers (Timeline, PetEdit, VetExport, and others) — unrelated to the app-wide overlay stack, and not affected by the containing-block mechanism since none of them compete with a second overlay the way `PetSymptoms.jsx`'s did.
- Does not change what any popup, dialog, or full-screen flow looks like, says, or does, and does not change `SymptomLogForm`'s own behavior — stacking order, positioning, and dead-code removal only.
- Does not audit for other possible unused files/components outside the 11 found already carrying a hardcoded z-index — this was a byproduct of the z-index audit, not a general dead-code sweep of the whole codebase.
